E2fsprogs1.47.4: https://www.kernel.org/pub/linux/kernel/people/tytso/e2fsprogs/v1.47.4/e2fsprogs-1.47.4.tar.xz

Both exact upstream source archives accompany every binary release in the APK asset native-corresponding-source.zip, together with the original MIT block adapter and build scripts. The APK's About screen can export that source archive. No third-party source is modified. The original native/android_compat.h shim supplies hasmntopt on API23–25 (the platform adds it at26): builds run out of tree; e2fsprogs make LN is overridden to cp because Android app storage prohibits hardlinks here. GPL/LGPL/BSD/MIT notices remain in the source archives. Separately executed tools do not link the Java UI into their address space.

Build on the Lenovo tablet: extract the archives into .downloads/native-src/, then bash scripts/build_native.sh. The installed Termux clang21 cross-compiles with Android API23 headers/stubs and builtins from the official NDK r30. tools/ndk_headers.py describes and meters selective ZIP range extraction; it does not require running x86 host executables. tools/native_cc.py supplies per-ABI API23 target/sysroot and 16KiB ELF alignment. The resulting fixed utilities are packaged in jniLibs and run from Android's extracted readonly nativeLibraryDir; there are no downloaded runtime executables, root operations or shell commands.

The owned usb_bridge.c adapter intercepts /dev/usbworkbench and sends bounded read/write/sync requests through pipes. Java NativeProtocol owns actual permission-checked USB I/O, enforces partition bounds and read-only operations, and verifies writes. No full-drive temporary image is created on the phone. Real USB, power-loss and older Android tests remain necessary. Native format engines are experimental pending that matrix.

## FAT/exFAT checkers in0.9
`bash scripts/build_fscheck.sh` reuses the cached dosfstools4.2/exfatprogs1.3.0 archives (digests checked against the original quota receipts), configures four API23 ABIs, static exfat library, no iconv/extra dynamic dependencies,16KiB ELF alignment. Upstream files remain unmodified. `-std=gnu11` keeps the older configure probes compatible with Clang21. The shared I/O bridge handles partition-relative seek/read/write and hard-disables writes during `-n` checks. FAT `-V` is verify, not version: preflight uses `--help`; exFAT help deliberately returns16. Repair uses upstream automatic `-p`, accepts corrected status1, then requires a separate read-only check. No journal replay for NTFS or full Windows chkdsk claim.

## 0.10 streaming readers

scripts/build_archive.sh builds libarchive3.8.11/liblzma5.8.4 and the original archive_cli.c with bounded in-process decoders (archive_lzma_limits.c). scripts/build_chd.sh builds pinned libchdr0.3.0 and the original read-only CHDv5 HD/DVD adapter; chd_compat.h supports API23 without changing the 64-bit virtual-file path. scripts/build_fsimage.sh builds original GPL2+ NTFS/ext read-only traversal adapters using the existing cached upstream libraries. All four API23 ABIs are independently compiled; audit_native.py verifies 80 ELF files, alignment and system-only dependencies. Native source export uses the deterministic curated libarchive runtime source with full per-file provenance; the full project source also includes its official complete archive. No upstream runtime code is patched. Android mounts and external shell/filter helpers are not used. See THIRD_PARTY.md and LICENSES for licenses and source details.

## 0.11 bounded WIM tree adapter

Original GPL3+ wim_tree.c is merged into each existing imagex executable: build_wim.sh compiles upstream normally, copies/renames only its main object symbol, and links the original dispatcher against that same static libwim. Upstream sources remain unchanged. usbwb-tree-list/all accept fixed input plus index/limit/subtree and emit bounded UWARCH01 metadata/fixed numbered regular-file outputs. No archive path is passed to OS output APIs. Link/reparse/encrypted/special/named-stream entries are S and omitted, hard-link contents are separate files without relationship restoration. Up to10000paths/1000files/depth128/16GiBoutput. Only adapter TO_STDOUT data is redirected into the active numbered virtual file; all other writes delegate through the existing preload bridge. One process per tree export; no per-file subprocess or new full-engine library. Existing WIM CLI regression tests retained.
